# Coding Requirements

Requirements for all code in this repository.

## General

- All source code, unit tests, and integration tests are generated by Claude based on requirements documents
- Code must be clear, maintainable, and well-structured

## Language Boundaries

| Layer | Language | Why |
|-------|----------|-----|
| Core data types, wire protocols, bound/threshold evaluation, (next) streaming pub/sub, monitors, loggers | **Rust** (`crates/`) | Performance on SBCs, latency budget, correctness guarantees |
| Python API over the core | **PyO3 bindings** (`hwtest-core/native/`) | Test cases import `hwtest_core` exactly as before |
| Test cases, instrument drivers under active bring-up, rack/runner glue | **Python** | Fast iteration on hardware; accessible to subject-matter experts |
| Test definitions, bounds, rack and station configuration | **YAML** | Declarative specs reviewed by non-developers |

Rules:
- The Rust crates are the single source of truth for data formats. Python must not reimplement
  serialization or bound logic; it calls the bindings.
- Wire formats (binary streaming frames, JSON messages, bound specs) are a compatibility contract.
  Changes require updating `crates/hwtest-core/tests/fixtures/` and the compatibility tests.
- Python-facing enums and exceptions stay defined in Python (`hwtest_core._enums`,
  `hwtest_core.errors`) and are mirrored in Rust.

## Python

### Style

- Follow PEP 8
- Maximum line length: 100 characters

### Formatting

- **black**: All code must be formatted with black
  - Line length: 100 (`black --line-length 100`)
  - Run before every commit

### Linting

- **pylint**: All code must pass pylint with no errors
  - Warnings should be minimized
  - Disabled rules must be justified with inline comments

### Type Hints

- **Full type coverage**: All functions, methods, and variables with non-obvious types must have type hints
- **mypy strict mode**: Code must pass `mypy --strict` with no errors
- Use `from __future__ import annotations` for modern annotation syntax
- Prefer built-in generics (`list`, `dict`) over `typing` module equivalents

### Testing

- Unit tests use pytest
- Test files mirror source structure in `tests/unit/`
- Integration tests in `tests/integration/`

### Dependencies

- Minimize external dependencies
- Pin versions in requirements files
- Document why each dependency is needed

## Rust

### Style and Linting

- `cargo fmt` (100 columns, see `rustfmt.toml`) before every commit
- `cargo clippy --workspace --all-targets` with `clippy::pedantic` must produce no warnings;
  any `#[allow(...)]` must carry a justification comment
- `unsafe` code is forbidden (`unsafe_code = "forbid"` workspace lint)
- All public items have doc comments (`missing_docs` lint); fallible functions document `# Errors`

### Structure

- Pure-Rust crates live in `crates/` and must not depend on PyO3
- PyO3 binding crates live next to the Python package they back (`hwtest-<pkg>/native/`) and
  contain only conversion glue, no domain logic
- Python extension modules use the stable ABI (`abi3-py310`) so one wheel serves all Python versions

### Testing

- Unit tests in each module (`#[cfg(test)]`); cross-language wire tests in `crates/*/tests/`
- Python behaviour of bindings is tested with pytest in the owning Python package

### Build System

- Cargo workspace at the repository root (`Cargo.toml`, committed `Cargo.lock`)
- Python packages with native code build with maturin (`pip install -e ./hwtest-core`)
- MSRV is set in `[workspace.package] rust-version`
